## What the automated leg decides, and why it is all seven

Both of this phase's gates are things the harness builds, so neither needs a room, a phone or a
person: TRI-004 synthesises a pair from depths the stage picked and never disclosed, and TRI-003
replaces a pair's second view with a pure rotation of its first. The rest is decided on the
parallax pan, which carries real structure at two depths.

From the committed run:

| | |
| --- | --- |
| Batches | 97 over a 60 s hold — 95 triangulated, 2 refused |
| Points | 9,267; median 92 per batch, 95.5 per keyframe |
| Parallax | median 4.30° over every candidate, worst **accepted** 1.001° against a 1.0° floor |
| Depth uncertainty | 0.053 against the 0.10 the floor was derived to buy |
| **TRI-004** | median relative depth error **0** against a constant depth's **0.234**; rank correlation **1** |
| **TRI-003** | **0** points from 16 pure rotations, 1,561 from the untouched pairs on the same batches; the pose came back `ROTATION_ONLY` 16 times out of 16 |
| TRI-006 | the pair fit says 0.047°, Phase 6's chain disagrees by 0.048° against a 3° tolerance, 74/74 inside |
| Scale | `LOCAL_UNITS`, baseline 1, batch-to-batch depth spread **0.96** |
| Cost | 11.7 ms per batch, 1.8 ms amortised over every frame |

**The depth error is exactly 0, and that is correct.** The injected pair is synthesised exactly —
the harness picks the depths and projects them through a known `(R, t)` — so a linear solve on it
is exact to numerical precision. The number that makes it mean something is the control printed
beside it: what the best possible single constant depth would have scored on the same set.

**The batch-to-batch depth spread is 0.96, on one scene with one camera.** That is the number
behind TRI-007's refusal to pool depths: the median depth moves by 96 % of itself between batches,
not because the room changed but because each pair's baseline is a different unit.

## What the fixture proved that the leg cannot

`tests/unit/triangulation.test.ts` drives the real `TriangulationStage` — the real batching, the
real fit, the real injections — with a triangulator that returns **one constant depth** and
reports a small reprojection error for every point. It fails **TRI-004 and nothing else**:
TRI-001, TRI-002, TRI-003, TRI-005, TRI-006 and TRI-007 all pass, and its reported reprojection
error is *better* than the real triangulator's. That is the plan's claim, executed rather than
asserted.

## Two corrections the measurements forced

**"On a sampled schedule" was sampled on the wrong cadence.** The injections were requested by a
flag the composition root sets on its own option cadence, which is how Phases 5 and 6 do it — and
those phases sample *frames*, while this one's unit of work is a **batch** that happens when
Phase 8 inserts a keyframe. The main thread does not know when that is, and the leg measured an
injection on **64 % of batches** at 20.9 ms each. The stage samples on its own batch index now,
one in six for each, and the same leg measures 11.7 ms.

**A noiseless fixture cannot exercise TRI-006's third criterion.** The unit fixture first built
its keyframes by exact projection, so the pair fit and Phase 6's route agreed to the last decimal
on every batch — and TRI-006's *not identically zero* criterion fired, correctly, on the fixture
rather than on a defect. A fifth of §13's 1.5 px band is now added to every observation, which is
what a well-tracked point actually looks like.

## The cost, and the worker §B.2 has been planning since before Phase 0

11.7 ms per batch on this machine, against a ceiling this phase set for itself at 8.0. TRI-008 is
advisory and excluded from the leg's gate for the reason every cost record is — a device budget
cannot be adjudicated off the device (§H.4) — but the number is worth reading: it is dominated by
the pair's own RANSAC fit, over more correspondences and a longer baseline than the anchor pair
Phase 5 fits every frame.

**1.8 ms amortised over every frame** is what §B.2's mapping-worker decision should be taken on.
The worker is not built, and the plan has had it in the diagram since before Phase 0; the argument
for building it is a measurement rather than a diagram, and this is the measurement to watch when
the device produces its own.
