## What the automated leg decides, and why it is all six

Phase 7's leg was the first in this project to decide a required record: v3 §68's pass condition
was about an absence that headless Chromium is permanently in. Phase 8's leg decides **the whole
required suite**, for a different reason — the instruments this phase is scored against are a
camera that is not moving and a metronome, and the harness can produce both. The feed holds still
for seven seconds in the middle of a pan; the metronome runs inside the app on the same frames.

**What the device will not reproduce, and why the run is still needed.** The leg's "still" is a
synthetic frame repeated exactly; a hand-held phone is not still, and Phase 4's search will often
call it `SLOW`. The leg's population runs to several hundred points; the device's ran to 41 in a
dim room (§H.8). Both change what the store holds and how quickly it goes stale. Rule 004 is not
a formality here.

## Two defects this leg found, before any device saw them

**A re-derivation that rounds its inputs is checking the formatter.** KEY-001's second criterion
re-derives every decision from the inputs recorded beside it. The first version rounded
`sinceLastMs` to a tenth of a millisecond on its way into the record, and `499.99999999999955`
became `500` — so the re-derivation disagreed with the stage on **every decision that landed on
v3 §20's minimum interval**, 30 of them in a 32-second unit fixture. The recorded inputs are now
the decision's inputs to the bit.

**Composing a per-frame increment over five seconds is a random walk.** The rotation since the
last keyframe was first accumulated the way `FusionStage` accumulates its visual increments —
`conj(q_prev) · q_cur`, composed every frame. Phase 7 composes over one second and is unaffected;
Phase 8 composes over up to five, and on the leg's lateral pan, where the true rotation is zero
throughout, the accumulated angle reached v3 §20's 10° and fired `ROTATION` **seven times while
the image was not moving at all**. It is now assembled per anchor epoch — one composition however
many frames have passed, and one more at each re-anchor — and the same leg fires it none.
`docs/phase8/TEST-PLAN.md` records the amendment beside the criterion it affects.

**And a cost that measured the fixture rather than the platform.** The eviction record carries the
retained set's median pairwise separation beside the counterfactual, and the first version built
one observation index per pair — 435 of them over a several-hundred-point population, which put
the mean keyframe cost at 1.67 ms against this phase's own 1.0 ms ceiling. Indexing each keyframe
once brings it inside. §H.8: a cost measured before the obvious inefficiency is removed is not a
measurement of the platform.
